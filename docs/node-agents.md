# Подключение агентов узлов

В разделе «Узлы» укажите имя, тип узла, адрес агента и ключ, который уже настроен в `NODE_AGENT_API_KEY` или `PROXY_AGENT_API_KEY`. По умолчанию VPN-агент слушает порт 9100, прокси-агент — 9101. Нажмите «Здоровье», чтобы проверить соединение и обновить статус узла. Активными можно делать VPN-узлы.

- Для HTTP укажите адрес вида `http://agent.example.org:9100`.
- Для HTTPS укажите адрес вида `https://agent.example.org:9100`. По умолчанию панель проверяет сертификат через системные центры доверия. Для собственного CA укажите имя его PEM-файла.
- Для существующего HTTPS + mTLS укажите имена PEM-файлов CA, клиентского сертификата и его закрытого ключа. Разместите файлы в подкаталоге `node-tls` каталога, переданного через `--data-dir`, и обеспечьте к ним доступ пользователя панели. На Linux используйте права `0700` для каталога, `0644` для сертификатов и `0600` для закрытого ключа.

Панель по умолчанию подключается к публичным IP-адресам. Для доверенных узлов во внутренней сети задайте `APAZ_ALLOW_INTERNAL_NODES=true` в окружении сервиса. При HTTP ключ передаётся без шифрования, поэтому для связи через публичную сеть используйте HTTPS.

В разделе «Прокси» доступны проверка статуса переадресации, изменение IPv4-адреса назначения и просмотр соответствий активных подключений. Для изменения адреса прокси-агент должен быть уже установлен и видеть действующие правила переадресации.

Регрессионная проверка запускает синтетические агенты на loopback и использует одноразовый центр сертификации. Для неё нужны собранный бинарник панели, Python и утилита OpenSSL.

```sh
python3 tests/nodes.py ./build/adminpanelaz-lws
```
