# Приёмка полного переноса AdminPanelAZ

Эталон поведения и форматов — AdminPanelAZ на коммите [d6ccd0098](https://github.com/Kirito0098/AdminPanelAZ/tree/d6ccd0098b04463471332c244364ffbe05a3d156). Целевая поставка использует C, libwebsockets и встроенный интерфейс на HTML, CSS и JavaScript. Для существующих агентов, VPN-клиентов, архивов, ссылок портала и Telegram сохраняются внешние контракты. Встроенная панель может использовать собственные внутренние маршруты, если соответствующие пользовательские сценарии работают полностью. [Карта оригинала](https://github.com/Kirito0098/AdminPanelAZ/blob/d6ccd0098/docs/PROJECT_MAP.md)

Для сверки состава экранов и оформления используется [наблюдаемый интерфейс оригинальной панели](ui-reference.md).

## Внешние контракты для тестов совместимости

- **Агенты.** Сверять реальные HTTP-методы, заголовок `X-Node-Key`, статусы и JSON, сертификаты и SSH-подключение. У VPN-агента есть `/health`, семейства `/clients/*`, `/server-monitor/*`, `/configs/*`, операции PKI и архивов. У proxy agent есть `/health`, `/proxy/status`, `/proxy/destination`, `/proxy/mappings`. Проверить C-панель со старыми агентами. Если поставка заменяет сами агенты, проверить обратную комбинацию с эталонной панелью. [VPN-агент](https://github.com/Kirito0098/AdminPanelAZ/blob/d6ccd0098/backend/node_agent/main.py) · [Прокси-агент](https://github.com/Kirito0098/AdminPanelAZ/blob/d6ccd0098/backend/proxy_agent/main.py)
- **HA.** Управление `/api/nodes/sync-groups` включает `setup`, `push-full`, `apply-shared-domain`, `verify` и `status`. Сверить допустимые версии агентов, форматы экспорта и импорта OpenVPN, восстановление с `ha_replica=true` и сохранение локальных исключений реплики. [Контракт Node Sync](https://github.com/Kirito0098/AdminPanelAZ/blob/d6ccd0098/docs/NodeSync.md#api)
- **Файлы.** Проверять байты и имена профилей, варианты протоколов, `Content-Type` и `Content-Disposition`. В архивах эталона сверять `data/adminpanel.db`, `data/cidr/cidr.db`, `env/.env` и опциональные слои. Upstream `POST /api/backups/upload` принимает multipart-поля `file`, `restore` и `password`. Текущий маршрут C-порта принимает `application/octet-stream`. Совместимость проверять с фактическими клиентами каждого формата. [Архивы API](https://github.com/Kirito0098/AdminPanelAZ/blob/d6ccd0098/backend/app/routers/backups.py) · [Выдача файлов](https://github.com/Kirito0098/AdminPanelAZ/blob/d6ccd0098/backend/app/services/file_download.py)
- **Telegram и портал.** Проверять префикс `ACCESS_PATH`, публичный API портала на `/api/public/portal/{token}`, страницы `/p/…`, существующие URL Mini App и входа Telegram. У `POST /api/telegram/webhook/{secret}` проверять секрет пути, секретный заголовок Telegram согласно настройке, фильтр IP и дедупликацию по `update_id`. ## Порядок проверки одного выпуска

1. Поднять эталон и перенос с раздельными копиями исходных данных. Для записей использовать отдельные тестовые узлы. Зафиксировать версии ОС, VPN, агентов, исходных БД и архива.
2. Для каждой строки матрицы сохранить результаты сценария и сравнить HTTP-ответы, файлы, события и состояние после записи. Проверить сценарии через встроенный HTML/JS-интерфейс и через соответствующее внешнее подключение. Прогнать отказ прав доступа, обрыв запроса и перезапуск во время длительной операции.
3. Прогнать [smoke-тест](../tests/smoke.py) и [тест лимита памяти](../tests/memory_budget.py). Дополнительно измерить пик памяти и задержки API при параллельных обновлениях мониторинга, передаче архива и фоновой операции. Проверить чистую установку и обновление на Ubuntu 24.04 и Debian 13.
4. Проверить на стенде миграцию с существующей установки, сохранение рабочих профилей и откат с восстановлением данных и доступа. Собрать один выпуск после приёмки всех строк, затем применить его к рабочему развёртыванию.
